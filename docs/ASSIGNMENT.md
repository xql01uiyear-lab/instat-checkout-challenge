# Оформление заказа

Сделайте фронтенд небольшого магазина на React и TypeScript. Бэкенд находится в этом репозитории. Можно использовать Next.js или Vite; остальные библиотеки — на ваше усмотрение.

Макета нет. Нужен аккуратный интерфейс, удобный на компьютере и телефоне. Проверим ширину 1280 и 390 пикселей, подписи полей и работу формы с клавиатуры.

## Что должен уметь пользователь

1. Посмотреть товары и добавить доступный товар в корзину.
2. Открыть корзину, изменить количество или удалить позицию. Увидеть общую стоимость.
3. Перейти к оформлению, заполнить имя, email и телефон. Выбрать самовывоз с пунктом выдачи или курьерскую доставку с адресом. Получить стоимость доставки и итоговую сумму от сервера.
4. Выбрать оплату картой или наличными при получении. Для карты — открыть тестовую платёжную форму, выбрать карту из API и нажать «Оплатить». Предусмотреть отмену.
5. Дождаться результата. После подтверждения оплаты показать страницу успеха с номером заказа, товарами, доставкой и суммой. Для наличных — сообщение «Заказ оформлен, оплата при получении».

Форма оплаты не должна принимать настоящий номер карты или CVC. Достаточно выбора тестовой карты по названию и маске.

## Что учесть

- Пустую корзину, недоступный товар, загрузку и ошибки API.
- Ошибки заполнения формы. При ошибке запроса введённые данные должны сохраняться.
- Отказ карты и отмену оплаты. Пользователь должен иметь возможность повторно оплатить тот же заказ.
- Двойное нажатие кнопок оформления и оплаты. Для повторных запросов используйте предусмотренный API ключ идемпотентности.
- Перезагрузку страницы: восстановите сессию, корзину и текущий заказ. Если оплата ещё обрабатывается, продолжите проверять её статус.
- Остановку опроса после завершения оплаты или ухода со страницы. Запоздавший ответ не должен подменять более свежие данные.
- Изменившуюся корзину или устаревший расчёт: обновите данные и дайте продолжить оформление.

Страница успеха должна получать статус заказа от сервера. Переход по ссылке и успешная отправка запроса на оплату ещё не означают, что заказ оплачен.

## Что посмотрим в решении

[Критерии и баллы](EVALUATION.md) опубликованы заранее: **DRY и обобщение — 40, производительность — 10, основной сценарий — 20, устойчивость — 20, интерфейс — 5, запуск и описание — 5**.

Главное для нас — обобщение кода и минимум повторяющихся операций. Запросы должны проходить через общий механизм; одинаковые проверки HTTP-ответов, разбор тела и ошибок не должны повторяться в компонентах. Решение с такими повторами не проходит отбор. Компонент получает готовые данные или разобранную ошибку и отвечает за их отображение.

Проверим стоимость часто выполняемых операций: лишние проходы по массивам, промежуточные коллекции, копирования и повторные поиски снижают оценку. Ожидаем один проход там, где он даёт тот же результат без лишней работы. Важно понимать, как на обработку влияют типы элементов и дырки в массиве.

Среди решений, прошедших обязательные условия, сначала сравним обобщение кода, затем производительность, затем общую оценку.

В README коротко объясните устройство работы с API и распределение обязанностей. Разберите один реальный участок обработки данных: частоту вызова, число проходов и выделение памяти.

## Как сдать

Добавьте фронтенд в `apps/web` и пришлите ссылку на свой репозиторий с решением. В README укажите команды запуска и сборки фронтенда, принятые решения, проверенные сценарии и оставшиеся недоработки.

Регистрация, личный кабинет, админка и деплой не требуются. Бэкенд менять не нужно.

Можно пользоваться любыми библиотеками, документацией, поиском, нейросетями и помощниками для написания кода. На собеседовании нужно будет объяснить решение и внести небольшое изменение.

Нужно выполнить оба тестовых: [оформление заказа](https://github.com/instatdigital/frontend-checkout-challenge) и [канвас на React Flow](https://github.com/instatdigital/frontend-canvas-challenge). Пришлите ссылки на оба решения. Решения смотрим раз в три дня; кандидатов с наиболее удачными работами приглашаем на прямое техническое собеседование.
