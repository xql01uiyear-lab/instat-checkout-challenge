# Работа с API

Версия контракта: 1.0. Базовый адрес — `http://localhost:4000`. Все суммы указаны в копейках, валюта — `RUB`. Полные схемы и примеры находятся в Swagger на `/docs/`.

## Авторизация и ответы

`POST /api/sessions` с `{}` создаёт гостевую сессию. Сохраните `data.token` и передавайте `Authorization: Bearer <token>`. Новая сессия получает отдельную корзину. Токен действует до сброса данных. `data.id` — идентификатор сессии; это не токен.

Успешный ответ с телом:

```json
{
  "data": {},
  "meta": { "requestId": "идентификатор запроса" },
  "links": { "self": { "href": "/api/cart", "method": "GET" } }
}
```

`links` содержит адреса ресурсов и доступные действия. `href` — путь относительно адреса API, `method` — метод запроса. Начальный список ресурсов доступен через `GET /api`. Структура тел запросов описана в OpenAPI, ссылка `contract`.

Ошибка:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте формат и поля запроса.",
    "fields": [{ "path": "body/customer/email", "message": "must match format email" }]
  },
  "meta": { "requestId": "идентификатор запроса" }
}
```

`fields` может отсутствовать. Сообщения в нём технические; для полей формы можно использовать свои подписи. `X-Request-Id` совпадает с `meta.requestId`.

`POST` и `PUT` принимают `application/json`. Где указано `{}`, отправляйте пустой JSON-объект. `GET`, `HEAD` и `DELETE` тела не принимают. У `204` тела ответа нет — вызывать `response.json()` для него не нужно.

## Методы

Все методы ниже возвращают `400` при некорректном запросе. Внутренняя ошибка — `500`. Методы с JSON-телом также могут вернуть `413` при размере больше 32 КБ и `415` при другом Content-Type. Защищённые методы возвращают `401` с `WWW-Authenticate`, если токен отсутствует или не подходит.

| Метод и адрес                                              | Успех                                                                                         | Дополнительные ошибки |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------- |
| `GET /api`                                                 | 200, список ресурсов; без токена                                                              | —                     |
| `POST /api/sessions`                                       | 201 + Location; без токена                                                                    | —                     |
| `GET /api/sessions/{sessionId}`                            | 200, сессия и cartId                                                                          | 404                   |
| `GET /api/products`                                        | 200, каталог; без токена                                                                      | —                     |
| `GET /api/sandbox`                                         | 200, тестовые карты; без токена                                                               | —                     |
| `GET /api/cart`                                            | 200, корзина и её версия                                                                      | —                     |
| `GET /api/cart/items/{productId}`                          | 200, позиция                                                                                  | 404                   |
| `PUT /api/cart/items/{productId}`                          | 201 + Location для новой позиции, 200 для существующей                                        | 404, 409              |
| `DELETE /api/cart/items/{productId}`                       | 204, в том числе при повторном удалении                                                       | —                     |
| `GET /api/checkout/options`                                | 200, доставка и оплата                                                                        | —                     |
| `POST /api/quotes`                                         | 201 + Location, сохранённый расчёт                                                            | 409, 422              |
| `GET /api/quotes/{quoteId}`                                | 200, расчёт                                                                                   | 404                   |
| `POST /api/orders`                                         | 201 + Location; повтор по ключу — 200                                                         | 404, 409              |
| `GET /api/orders`                                          | 200, заказы от новых к старым                                                                 | —                     |
| `GET /api/orders/{orderId}`                                | 200, заказ и статус оплаты                                                                    | 404                   |
| `GET /api/orders/{orderId}/payments`                       | 200, попытки от новых к старым                                                                | 404                   |
| `POST /api/orders/{orderId}/payments`                      | 201 + Location; повтор по ключу — 200                                                         | 404, 409              |
| `GET /api/payments/{paymentId}`                            | 200, статус попытки                                                                           | 404                   |
| `POST /api/payments/{paymentId}/simulations`               | 202 + Location + Retry-After; при нулевой задержке — 201 + Location; завершённый повтор — 200 | 404, 409              |
| `GET /api/payments/{paymentId}/simulations/{simulationId}` | 200, результат имитации                                                                       | 404                   |

У каждого адреса с `GET` есть `HEAD` с теми же статусами и заголовками, без тела. `OPTIONS` возвращает `204` и `Allow`; неподдерживаемый метод по известному адресу — `405` и `Allow`. Неизвестный адрес — `404`. Для всех ответов API установлен `Cache-Control: no-store`.

`Location` содержит относительный адрес для чтения созданного ресурса или проверки обработки. Заголовки `Location`, `Retry-After`, `Allow`, `WWW-Authenticate`, `Link` и `X-Request-Id` доступны фронтенду через CORS.

## Покупка картой

1. Создайте сессию и получите каталог.
2. Добавьте товар: `PUT /api/cart/items/lamp-orbit` с `{"quantity":1}`. Количество абсолютное: повтор этого запроса не добавляет ещё одну штуку и не меняет версию корзины.
3. Получите `GET /api/cart`, затем `/api/checkout/options`.
4. Создайте расчёт через `POST /api/quotes` с текущей версией корзины и доставкой:

```json
{
  "cartVersion": 1,
  "delivery": { "method": "pickup", "pickupPointId": "point-center" }
}
```

Для курьера поле `delivery` выглядит так:

```json
{
  "method": "courier",
  "address": { "city": "Учебный", "street": "Примерная", "house": "10", "apartment": "1" }
}
```

Самовывоз бесплатный. Курьер стоит 39000 копеек; при сумме товаров от 500000 копеек доставка бесплатна. Для отображения используйте суммы из расчёта.

5. Создайте заказ через `POST /api/orders` с заголовком `Idempotency-Key`. В `quoteId` подставьте `data.id` расчёта:

```json
{
  "quoteId": "c2d1e2b8-8cd2-4d03-88d4-6bec58cda10a",
  "paymentMethod": "card",
  "customer": {
    "name": "Тестовый Покупатель",
    "email": "buyer@example.test",
    "phone": "+79990000000"
  }
}
```

UUID в примере нужно заменить полученным значением. Телефон: `+` и 10–15 цифр, первая цифра не ноль.

6. Создайте попытку: `POST /api/orders/{orderId}/payments`, тело `{}`, новый `Idempotency-Key`.
7. Получите тестовые карты через `GET /api/sandbox`. Выбранный сценарий отправьте в `POST /api/payments/{paymentId}/simulations`: `{"scenario":"success"}`, `{"scenario":"decline"}` или `{"scenario":"cancel"}`.
8. После `202` подождите указанное в `Retry-After` число секунд и читайте ресурс из `Location` либо саму попытку оплаты. Остановите опрос после `succeeded`, `failed` или `cancelled`.
9. Перед страницей успеха прочитайте заказ. Для карты должны быть `status=paid` и `paymentStatus=succeeded`. Для `cash_on_delivery` заказ сразу получает `confirmed / unpaid`, попытка онлайн-оплаты не нужна.

Корзина очищается при создании заказа. Отказ и отмена сохраняют заказ: для повтора создайте новую попытку с новым ключом, используя прежний `orderId`.

## Повторы и обновление данных

Для создания заказа и попытки оплаты обязателен `Idempotency-Key`: 8–128 символов, буквы, цифры, `_` и `-`. Подойдёт UUID. При сетевой ошибке повторите прежние тело и ключ. Ответ будет `200` с уже созданным объектом; первое создание возвращает `201`. Другие данные с прежним ключом дадут `409 IDEMPOTENCY_CONFLICT`.

В позиции можно изменить только quantity; остальные поля вычисляет сервер. Если одновременно пришли разные количества, сохраняется последнее принятое значение. После изменения количества или удаления позиции получите корзину заново. Расчёт привязан к её версии и действует 10 минут. Если товары или доставка изменились, нужен новый расчёт. `409 CART_VERSION_CONFLICT` и `409 QUOTE_EXPIRED` означают, что данные следует обновить. `422 CART_EMPTY` — в корзине нет товаров.

У одной попытки оплаты может быть только одна имитация. Повтор выбранного сценария безопасен; другой сценарий даст `409 PAYMENT_FINALIZED`. Ещё одна активная попытка оплаты того же заказа — `409 PAYMENT_IN_PROGRESS`. Уже оплаченный заказ — `409 ORDER_ALREADY_PAID`. Попытка оплатить наличный заказ онлайн — `409 PAYMENT_NOT_REQUIRED`.

Отказ карты возвращается как состояние: `GET` отвечает `200`, `data.status` равен `failed`, `failureCode` — `CARD_DECLINED`. Это не HTTP-ошибка. Сценарий cancel имитирует закрытие формы без оплаты. Возврат уже списанных денег в задание не входит.

Сохраните token, orderId и paymentId для перезагрузки страницы. Если потеряли идентификатор попытки, запросите её список у заказа; если потеряли orderId — список заказов. Результат оплаты определяется сохранёнными сценарием и сроком завершения, поэтому переживает перезапуск сервера. Чтение статуса не записывает данные.

## Условные запросы и формат тела

На чтении совпавший `If-None-Match` даёт 304 без тела, несовпавший `If-Match` — 412. На изменении неисполненное условие даёт 412 до записи. Значение `*` проверяет наличие представления ресурса по адресу запроса. Коллекция существует даже тогда, когда пуста; поэтому `If-None-Match: *` на POST коллекции не означает «создать уникальный элемент» и вернёт 412. Для защиты от повторного создания используйте описанный выше Idempotency-Key.

API не выдаёт ETag. У ресурсов проверка конкретного значения If-Match не может совпасть; для них используют версию в теле там, где она предусмотрена контрактом. Пустые элементы списка ETag пропускаются, неправильный синтаксис даёт 400. If-Match сравнивается строго, If-None-Match допускает слабое сравнение. Ошибки авторизации, маршрута и отсутствующего ресурса сохраняют свои статусы.

Тело передавайте как JSON в UTF-8, без сжатия. Неподдерживаемый Content-Encoding, например gzip, даёт 415 UNSUPPORTED_CONTENT_ENCODING и Accept-Encoding: identity. При 415 из-за Content-Type заголовок Accept-Encoding отсутствует.

Эти правила описывают поведение бэкенда. В тестовом не нужно реализовывать условное кэширование, разбор списков ETag или проверку всех методов из Swagger. Требования к фронтенду перечислены в задании и критериях оценки.
